# Flutter widget captures

Ten 390 × 844 PNGs were rendered by `flutter test test/ui_capture_test.dart --reporter expanded` with `RepaintBoundary.toImage`, from the actual production `LoginScreen`, `DashboardDosenScreen`, `BuatSesiScreen`, `DetailSesiDosenScreen`, `DashboardMahasiswaScreen`, and `RiwayatScreen`. The status correction modal and validation state are triggered on those production widgets. Roboto and MaterialIcons are loaded explicitly because Flutter's widget-test default Ahem font renders text as blocks. The test uses the project's `AppTheme` and a fixed viewport, disables the debug banner, and checks expected widget text and Flutter layout exceptions before saving.

`CaptureSessionService` and `CaptureAuthProvider` in the test supply **invented demonstration records**, not Firebase data. The lecturer dashboard, session detail, roster, and history use fake in-memory streams/results. The login form is not submitted; code entry is not submitted; validation is the production form's local validator. These images are **not** device screenshots and do **not** demonstrate Firebase authentication, realtime database permissions, or Android E2E behavior. No Android emulator or web runtime was used. Font paths currently resolve via `FLUTTER_ROOT` or the SDK location `C:/src/flutter/flutter` on this host; porting the capture requires suitable Roboto/MaterialIcons font files.

Review: PNG dimensions and count checked by Pillow; production widget text and exception checks pass. Visually inspected active code and roster/status screenshots with readable glyphs and no overflow stripes. Long app-bar names on lecturer/student dashboards and roster names have since been bounded with ellipsis in production source; the captures were regenerated by the final Flutter test run. Screens show the viewport of a scrollable page, not content below the fold.
